# 🔴 重要修正：充电控制命令实际不可用

> 2026-09-25 诚实复盘

## 我之前的错误声明

我曾告诉用户：
> "✅ 实测命令成功下发（返回 requestId，不再 2009）"
> "VAT scope 加入 ChargingControl 后，充电命令打通了"

**这是错误的。**

## 实测证据（同一时刻、同一 token 体系）

| 命令 | 结果 |
|---|---|
| `remoteVehSearch`（寻车）| ✅ `pushState=5 resultCode=0 msg=执行成功` |
| `remoteVehACSmartControl`（空调）| ✅ 成功 |
| **`remote_charge_control`**（充电）| ❌ `pushState=7 resultCode=2009 执行失败，请重试` |

**★ 对照组证明：token / scope / 签名 / 网络 都正常，只有充电命令失败。**

## 我为什么会误判

```
当时的验证：
  res = api.send_command_raw("remote_charge_control", cmd)
  print(res)  → {"requestId": "0h00SjjWGZJt9TWr000"}
  ★ 我以为"返回 requestId = 成功"

实际情况：
  requestId 只是【受理凭证】
  真正的执行结果要用 cmd-result 端点轮询：
    pushState=5 → 成功
    pushState=7 → 失败（这里是 2009）

后来的 send_command（含轮询）→ 立刻暴露 2009
```

## 因此无效的改动

| 改动 | 状态 |
|---|---|
| `VAT_SCOPE_COMMANDS` 加 `"ChargingControl"` | ❌ 无效（对照实验证明 scope 不影响）|
| `switch.预约充电` | ⚠️ 命令会失败 |
| `select.充电模式` | ⚠️ 命令会失败 |
| `time.充电开始/结束时间` | ⚠️ 命令会失败 |
| `number.充电上限` | ⚠️ 命令会失败 |

## 为什么 App 能成功？

App 用的是【新式 job 通道】，与我们的传统 cmd/send 不同：

```javascript
// App 的真实调用（index.vehicle.js）
sendVehicleJob({
  controlKey: "LXVehicleControlTypeStartCharging",
  controlMap: {cmdKey: "remote_charge_control", ...},
  destParams: "mob.metaJobService.remoteChargingControl",
  jobTimeout: 40
})
```

而 smali 证据表明新式通道需要【JOB 类型的 token】：
```smali
// XAbsHttpControl.smali
const-string p1, "JOB"
invoke-interface {v0, v1, p1, v2},
    Lcom/chehejia/lib/vehicle/demand/OtherCapable;->getIDAADSVehicleToken(
        Ljava/lang/String;   ← VIN
        Ljava/lang/String;   ← "JOB"  ★ token 类型
        CallbackFunParams1;)
```

## 尝试过的方案（全部失败）

| 方案 | cmdKey | 结果 |
|---|---|---|
| ① 传统格式 | `remote_charge_control` | ❌ 2009 |
| ② controlType 名 | `LXVehicleControlTypeStartCharging` | ❌ 2009 |
| ③ 动作名 | `MoveOffModify` | ❌ 2009 |
| ④ jobService 名 | `mob.metaJobService.MoveOffOnTimeData` | ❌ 2009 |
| ⑤ jobService 简名 | `MoveOffOnTimeData` | ❌ 2009 |
| ⑥ 嵌套格式 | `{destParams, data, timestamp}` | ❌ 2009 |
| ⑥ 加 7 种 scope | AppointmentAC / MoveOff / ... | ❌ 2009 |

## 下一步（需要用户决策）

### 方案 A：抓包（最可靠）
在手机上用 App 操作一次充电设置，用 Charles/mitmproxy 抓 `cmd/send` 的真实请求体。

### 方案 B：反编译新版 APK（8.25.3）
新版是 Hermes 字节码，需要用 hermes-dec 或 hbctool 反编译，
找 `getIDAADSVehicleToken("JOB")` 的实现。

### 方案 C：接受现状
把充电相关的可控实体改成只读 sensor，或标注"实验性"。

## 教训

**必须用 `send_command`（含 cmd-result 轮询）验证，不能用 `send_command_raw`。**
`send_command_raw` 只返回受理凭证，不代表执行成功。
